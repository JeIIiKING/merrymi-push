# 메리미 웹 푸시 테스트

매일 밤 9시 **ON AIR** 알림이 갤럭시·아이폰에 실제로 오는지 확인하는 시제품.
본 사이트에 그대로 옮겨 쓸 수 있게 `서버 / 서비스 워커 / 구독 페이지`를 나눠 뒀다.

```
server.js              발송·구독·예약·도착 기록 API (의존성: web-push 하나)
public/index.html      구독 페이지 ("방송 알림 받기", 상태 표시, 셀프 테스트)
public/app.js          구독 페이지 스크립트
public/sw.js           서비스 워커 (푸시 수신, 알림 탭 → 방송 화면 이동, 도착 보고)
public/onair.html      임시 방송 화면
public/admin.html      관리자 (즉시 발송, 매일 예약, 1회 예약, 기기 목록, 도착/지연 기록)
public/manifest.webmanifest  PWA 설정 (홈 화면 추가)
```

---

## 1. 내 컴퓨터에서 실행

```bash
npm install
npm run keys          # VAPID 키 한 쌍 출력 → .env 에 붙여넣기
cp .env.example .env  # ADMIN_KEY, VAPID_*, VAPID_SUBJECT 채우기
npm start             # http://localhost:3000
```

> 폰 테스트는 **HTTPS 주소가 꼭 필요**하다 (localhost 제외). 아래 배포로 진행할 것.

## 2. 배포 (예: Render 무료)

1. 이 폴더를 GitHub 저장소에 올린다 (`.env`, `data/`는 올리지 않음 — .gitignore 처리됨).
2. Render → New → **Web Service** → 저장소 선택
   - Build: `npm install` / Start: `npm start`
3. Environment에 `.env` 항목 입력: `ADMIN_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`(실제 메일, `mailto:`로 시작), `CRON_KEY`
4. 배포된 `https://…onrender.com` 주소를 죠르디에게 전달.

### 무료 서버가 잠드는 문제 (중요)
Render 무료는 15분간 요청이 없으면 잠들고, 잠든 동안에는 9시 예약이 돌지 않는다.
**cron-job.org**(무료)에서 아래 주소를 **10분마다** 호출하게 등록하면 깨어 있는 상태가 유지되고, 예약 확인도 같이 한다.

```
https://<내 주소>/api/cron?key=<CRON_KEY>
```

- 그래도 서버가 재시작되면 `data/`(구독 목록)가 지워질 수 있다. VAPID 키를 환경변수로 고정해 뒀다면 각 기기에서 **"기기 이름 저장 / 다시 등록"**만 다시 누르면 된다.
- 본 사이트에서는 구독 목록을 DB(Supabase, Firebase 등)에 저장하도록 바꾸면 된다 — `db.subs` 부분만 교체.

## 3. 테스트 진행

**관리자**: `https://<주소>/admin.html` → ADMIN_KEY 입력
**테스터**: `https://<주소>/` → 기기 이름 입력 → **방송 알림 받기** → 허용

도착 여부는 테스터가 말해주지 않아도 관리자 화면의 **발송 기록 · 도착 확인** 표에 자동으로 찍힌다
(기기의 서비스 워커가 알림을 받는 순간 서버에 보고 → 도착 시각, 지연 시간, 알림 탭 여부).

| # | 테스트 | 방법 | 기대 결과 |
|---|---|---|---|
| 1 | 갤럭시 크롬 · 브라우저 닫힘 | 구독 → **30초 뒤 보내기** → 최근 앱에서 크롬 밀어서 종료 | 알림 옴 ✅ |
| 2 | 갤럭시 삼성 인터넷 · 닫힘 | 같은 방법 (기기 이름을 다르게) | 알림 옴 ✅ |
| 3 | 갤럭시 절전 모드 켬/끔 | 화면 끄고 5분 이상 둔 뒤 관리자에서 즉시 발송, 켬/끔 각각 | 지연 시간 비교 (켬일 때 늦거나 안 오면 절전 예외 필요) |
| 4 | 아이폰 사파리 탭 | 사파리로 접속 | "미지원 (사파리 탭)" 표시, 구독 불가 = 정상 |
| 5 | 아이폰 홈 화면 앱 | 홈 화면 추가 → 아이콘으로 열기 → 구독 → 앱 닫고 발송 | 알림 옴 ✅ (iOS 16.4+) |
| 6 | 예약 정시 도착 | 관리자 **1회 예약 2분 뒤** / 실제 21:00 예약 | 표의 "지연"이 수 초 이내 |
| 7 | 알림 탭 이동 | 받은 알림 탭 | 방송 화면에 "✅ 알림(#…)을 눌러서 들어왔어요" + 관리자 표에 "탭함" |

**성공 기준**: 죠르디 갤럭시 #1 통과, 아이폰 #5 통과.

### 결과 읽는 법
- **푸시서버 응답 201** = 구글/애플 푸시 서버가 접수함 (서버 쪽은 정상)
- **기기 도착 + 지연** = 실제로 폰까지 옴
- 201인데 **대기/미확인**이 계속 = 폰에서 막힘 → 절전·알림 권한·방해 금지 모드 확인
- **410/404** = 구독 만료 → 자동 삭제됨, 기기에서 다시 등록
- 아이폰에서 **403 BadJwtToken** = `VAPID_SUBJECT`가 실제 메일 주소인지 확인

## 4. 본 사이트로 옮길 때

- **알림 종류 추가**: `sendPush({ title, body, url })`만 호출하면 됨
  - 방송 시작 → `/onair`
  - 응답 마감 임박 → `/answer`
  - 단서 지급 → `/clues`
- **개장 안내 가이드**: `index.html`의 iOS 안내 / 갤럭시 절전 안내 카드를 그대로 사용
- **알림 실패 안전망(사이트 안 배지)**: 발송 기록(`logs`)에 이미 기기별 도착 여부가 있음 →
  "도착 안 함"이거나 "탭 안 함"인 항목을 사용자별로 모아 사이트 상단 배지(놓친 방송·새 단서·미응답)로 표시
- 구독은 지금 **기기 단위**. 본 사이트에서는 로그인한 러너 ID와 묶어 저장해야 개인별 알림(미응답 알림 등)이 가능
